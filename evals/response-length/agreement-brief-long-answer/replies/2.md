Nothing changes for that repository, which is the whole point of how the fallback was written.
When `hooks/branch-guard` cannot find a `.claude/arc/camp/operating-agreement.md` at the
repository root, or finds one with no **Branch prefix** line in it, the value it uses is
`arc/` — exactly the string that used to be compiled into the `case` pattern before the clause
existed. So a repository that has never opened the agreement behaves the way it behaved
before, and a repository that has opened it gets whatever it typed. The read is bounded at the
root deliberately: `camp-branch-check` walks up the directory tree looking for `CLAUDE.md`,
and doing that here could reach a `.claude/` directory belonging to some enclosing checkout
entirely outside this repository, which would mean a per-repository setting was being read
from somewhere that is not the repository. One `git rev-parse --show-toplevel`, then one file
test, and no walk at all.
